# 微信公众号新闻同步

公众号来源位于管理端“新闻管理 → 公众号来源”。每个来源可配置发布范围、同步间隔、标题关键词，以及同步后的发布方式。标签栏右侧的“WeRSS 面板”以新窗口打开采集管理页面。

WeRSS 负责订阅与采集，TasteInsight 的后台任务负责定时导入。生产环境由 worker 执行任务，宿主机开发由 `start:dev` 启动的后端执行。

## 选择接入方式

| 场景 | 服务地址 `WERSS_BASE_URL` | 浏览器面板地址 `WERSS_ADMIN_URL` | 启动方式 |
|---|---|---|---|
| 宿主机开发 | `http://127.0.0.1:8001` | `http://localhost:5173/werss/`，端口随 Vite 调整 | 主 Compose 单独启动 `werss`，Vite 代理面板 |
| 完整 Compose 部署 | `http://werss:8001` | `https://admin.example.com/werss/` | 启用 `werss` profile，Nginx 代理面板 |
| 已有独立 WeRSS | 后端可访问的服务根地址 | 浏览器可访问的面板地址 | 只填写连接配置 |

`werss` profile 负责选择同机采集容器；后端的 `WERSS_BASE_URL`、`WERSS_ACCESS_KEY`、`WERSS_SECRET_KEY` 三项齐全时，管理端显示“公众号来源”与面板入口。省略接入配置时，新闻管理保留手动录入。已同步新闻继续按草稿、发布和撤回状态管理。

## 账号与密钥

| 配置 | 用途 |
|---|---|
| TasteInsight 管理账号 | 登录新闻管理，受新闻查看、编辑和发布权限控制 |
| `WERSS_USERNAME` / `WERSS_PASSWORD` | 初始化独立的 WeRSS 管理账号，用于登录采集面板 |
| `WERSS_SESSION_SECRET` | WeRSS 会话签名密钥，可用 `openssl rand -hex 32` 生成 |
| `WERSS_ACCESS_KEY` / `WERSS_SECRET_KEY` | 在 WeRSS 面板创建的 AK/SK，供 TasteInsight 后端调用采集接口 |

这些账号与密钥分别配置。AK/SK 仅保存在后端私有环境文件中。已有数据卷中的 WeRSS 用户沿用原密码；修改 `WERSS_PASSWORD` 只影响新建用户，已有账号通过面板修改密码。

## 宿主机开发

### 1. 准备后端与采集服务配置

先按 [本地开发说明](./环境配置与部署.md#本地开发) 准备 PostgreSQL、Redis、后端 `backend/.env` 和数据库迁移。保留已填写的数据库、Redis 与 JWT 配置，在同一文件中添加：

```dotenv
WERSS_BASE_URL=http://127.0.0.1:8001
WERSS_ADMIN_URL=http://localhost:5173/werss/
WERSS_USERNAME=admin
WERSS_PASSWORD=<独立的 WeRSS 登录密码>
WERSS_SESSION_SECRET=<随机会话签名密钥>
```

`5173` 应与管理端实际 Vite 端口一致。以下命令均在 `backend` 目录执行，采集服务使用固定项目名 `tasteinsight-werss-local`，与开发数据库所在的 `tasteinsight-dev` 项目分别管理：

```bash
docker compose -p tasteinsight-werss-local --env-file .env --profile werss up -d --build --wait werss
```

该命令只启动采集服务。主 Compose 解析时仍会检查数据库、Redis、JWT 和应用地址等必填变量，这些值来自已经填写的 `backend/.env`。

### 2. 配置面板代理并创建 API 密钥

在 `frontend-web/.env.development.local` 中添加：

```dotenv
WERSS_PROXY_TARGET=http://127.0.0.1:8001
```

重启 Vite 后，直接访问 `http://localhost:5173/werss/`。使用 WeRSS 账号登录，完成微信读书授权、订阅公众号，并在面板中创建 AK/SK。首次配置 API 密钥前，可直接访问此路径完成初始化；新闻管理中的入口将在后端连接配置完整后显示。

将密钥加入 `backend/.env`：

```dotenv
WERSS_ACCESS_KEY=<WeRSS API key>
WERSS_SECRET_KEY=<WeRSS API secret>
```

重启宿主机后端，刷新新闻管理页，即可进入“公众号来源”。Vite 代理支持页面、接口、静态资源与 WebSocket。更改宿主机映射端口时，同时调整 `WERSS_PORT`、`WERSS_BASE_URL` 和 `WERSS_PROXY_TARGET`。

## 完整 Compose 部署

### 1. 启用可选服务

准备两个域名的 DNS 和网关证书，配置要求见 [全新部署说明](./环境配置与部署.md#全新部署)。首次在 `backend` 目录创建私有配置：

```bash
cp .env.production.example .env.production
chmod 600 .env.production
```

填写数据库、Redis、JWT、应用域名、TLS 和首次管理员配置；已有部署沿用原私有文件及项目名。再添加采集配置：

```dotenv
COMPOSE_PROFILES=werss
WERSS_BASE_URL=http://werss:8001
WERSS_ADMIN_URL=https://admin.example.com/werss/
WERSS_USERNAME=admin
WERSS_PASSWORD=<独立的 WeRSS 登录密码>
WERSS_SESSION_SECRET=<随机会话签名密钥>
```

`WERSS_ADMIN_URL` 省略时使用 `ADMIN_APP_URL/werss/`。同时启用 Python 嵌入服务时，使用一条 `COMPOSE_PROFILES=embedding,werss`。API 与 worker 使用相同的 WeRSS 连接配置。以下命令均在 `backend` 目录执行。

### 2. 构建并启动服务栈

源码部署构建后端、前端与配套采集镜像，再启动应用和管理域名网关：

```bash
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production build public-api frontend werss
docker compose --env-file .env.production up -d --wait --wait-timeout 180 public-api admin-api worker frontend
docker compose --env-file .env.production up -d --no-deps --force-recreate --wait --wait-timeout 60 nginx
```

启用 profile 后，API 与 worker 的可选健康依赖会带起 WeRSS。此时 `WERSS_BASE_URL` 已让网关开放 `/werss/` 面板路径，首次授权可直接在管理域名完成；新闻管理中的公众号入口与定时扫描将在 AK/SK 配置齐全后启用。

### 3. 登录授权并接入导入

通过 `https://admin.example.com/werss/` 登录 WeRSS，完成微信读书授权、订阅公众号和 AK/SK 创建。将密钥写入服务器上的同一份 `.env.production`：

```dotenv
WERSS_ACCESS_KEY=<WeRSS API key>
WERSS_SECRET_KEY=<WeRSS API secret>
```

重新创建 API 与 worker，使其读取新密钥：

```bash
docker compose --env-file .env.production up -d --wait public-api admin-api worker
```

刷新新闻管理页后，即可配置公众号来源并从面板入口打开 WeRSS。镜像发布部署使用同一版本的后端、前端和配套 WeRSS 镜像；标准 CD 会构建并发布这三种镜像、复制网关配置并重建网关。

已运行环境新增接入配置时，沿用上述构建、网关启动、授权和密钥加载顺序。WeRSS 使用独立的 `werss_data` 卷，升级时保留原 `COMPOSE_PROJECT_NAME` 与数据卷。

### 路由与镜像

管理域名的 Nginx 为 `/werss/` 转发页面、接口、静态资源和 WebSocket；`/werss` 自动跳转到带斜杠路径。TLS 沿用管理域名的网关证书。公共 API 域名仅提供其原有路由。

容器间 API 始终使用服务根地址 `http://werss:8001`。宿主机映射仅绑定 `127.0.0.1:8001`，可通过 `WERSS_PORT` 调整。回环端口用于根路径 API 排障；浏览器面板通过 Vite 或 Nginx 的 `/werss/` 代理访问，代理负责去除请求前缀。

`backend/werss/Dockerfile` 固定上游 digest，并从同一版本源码构建支持 `/werss/` 的前端。`WERSS_IMAGE` 可指定兼容镜像的版本，默认发布标签与主服务一致。独立面板使用原版 WeRSS 时，按下面的“使用已有 WeRSS”配置其实际地址。

同域访问的配套镜像使用 DOMPurify 清理管理端正文，使用 nh3 清理服务端阅读页并限制脚本执行。内置应用壳、API 文档与固定阅读模板采用各自的页面策略，其余响应默认通过 sandbox 隔离主动内容，并发送 nosniff；上传文件额外限制资源加载。通用外站代理接口在配套镜像中关闭。采集接口与存储中的原文保持原样。

## 使用已有 WeRSS

管理员 API 和 worker 使用相同连接配置：

```dotenv
WERSS_BASE_URL=https://collector.example.com
WERSS_ADMIN_URL=https://collector.example.com
WERSS_ACCESS_KEY=<WeRSS API key>
WERSS_SECRET_KEY=<WeRSS API secret>
```

此方式省略 `werss` profile 和容器初始化凭据。`WERSS_BASE_URL` 填后端可访问的服务根地址，`WERSS_ADMIN_URL` 填浏览器可访问的 HTTP(S) 面板地址。显式指定独立面板地址时，网关关闭管理域名下的 `/werss/` 路由。

## 停用与维护

### 停用同步

从私有配置中移除 `werss` profile 与 `WERSS_BASE_URL`、`WERSS_ACCESS_KEY`、`WERSS_SECRET_KEY`。同时使用其他 profile 时保留相应名称。完整部署在 `backend` 目录执行：

```bash
docker compose --env-file .env.production up -d --wait public-api admin-api worker
docker compose --env-file .env.production --profile werss stop werss
docker compose --env-file .env.production up -d --no-deps --force-recreate --wait nginx
```

宿主机开发重启后端，并停止独立采集项目：

```bash
docker compose -p tasteinsight-werss-local --env-file .env --profile werss stop werss
```

后端重启后移除定时扫描计划，刷新管理页即可隐藏公众号入口。管理域名的 `/werss/` 随网关重建关闭；本地 Vite 代理可通过移除 `WERSS_PROXY_TARGET` 并重启关闭。采集容器、数据卷与已导入新闻保留。配置完整的服务临时离线时，入口继续显示，同步结果提示错误，恢复服务后可重试。

### 升级与数据

WeRSS 的数据库、订阅和授权数据保存在容器 `/app/data`，对应 Compose 的 `werss_data` 命名卷。备份时先停止采集容器，再复制完整的 `/app/data`，随后启动服务。该目录需要单独备份，TasteInsight 的 PostgreSQL 备份覆盖应用自身的新闻与来源数据。

源码升级使用 `up -d --build --wait werss`，镜像发布升级先拉取对应版本再重建该服务；沿用原私有配置、项目名和数据卷。宿主机开发沿用命令中的 `-p tasteinsight-werss-local`。`down -v` 会删除命名卷，普通停用与升级使用 `stop` 或 `up`。

默认采集模式为 `weread_mp`，`WERSS_GATHER_MODEL` 可选择上游支持的模式。授权失效后在 WeRSS 面板重新授权，再检查来源的同步状态。

## 同步来源

数据库迁移随标准部署流程执行。在“新闻管理 → 公众号来源”中选择已订阅的公众号。首次任务由 worker 在一分钟内扫描调度，后续按来源的同步间隔执行。同步结果和失败原因显示在来源列表，也可点击“立即同步”。暂停来源后停止导入，已保存的新闻继续保留。

## 发布方式

- **先存为草稿**：默认方式，管理员审核后发布。
- **直接发布**：选择后，新导入文章直接发布，发布时间为系统导入时间。配置与手动触发自动发布均需要 `news:publish` 权限。

后台任务每次执行都会重新核对来源负责人的账号、管理范围和发布权限。来源设置保存者成为后续同步的负责人。

修改发布方式只作用于新导入文章。已同步新闻的编辑内容、草稿与撤回状态保持原样；删除新闻后保留导入记录，后续同步继续跳过该文章。

## 内容展示

同步保存文章标题、正文、来源名称和微信原文链接，清理脚本、事件属性和外部 CSS 资源引用，保留可支持的行内样式、图片与表格。管理端仅修改标题、摘要时保留导入正文，点击“编辑正文”后进入富文本编辑器。

用户端通过 `mp-html` 展示导入正文，提供“查看微信原文”。H5 打开浏览器页面，App 调用系统浏览器，小程序优先使用微信文章入口，环境受限时提供复制链接。

原文的互动组件、脚本、部分复杂排版效果受客户端能力限制。完整微信页面通过原文入口查看。采集范围由 WeRSS 的采集模式与授权状态决定；导入器会分页读取 WeRSS 已保存的全部正文。上游没有提供可靠原始发布时间时，`sourcePublishedAt` 保持为空。
