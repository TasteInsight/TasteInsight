## 配置加载与运行角色

“默认值”指变量省略后的行为；模板为某种运行方式选取的值会单独标明。代码块为按功能拆分的示例，注释项供按需启用。所有 `<...>` 均为待替换占位符。密钥、口令与部署 env 文件应保持私有；`VITE_*` 会进入前端产物，只适合公开配置。

| 运行方式 | 配置来源与覆盖关系 |
|---|---|
| 宿主机开发 | 在 `backend` 运行开发命令，加载当前目录 `.env`；同名进程环境变量优先。`.env.example` 是开发起点。开发 `AppModule` 合并 API、后台和初始化能力 |
| 完整容器部署 | 从 `.env.production.example` 创建私有文件，用 `docker compose --env-file <文件>` 显式选择。Shell 同名变量优先于所选文件。Compose 按各服务 `environment` 映射注入字段，后端四角色固定 `NODE_ENV=production` |
| 独立生产进程 | 由进程管理器或部署环境注入变量；Nest 和数据库工具在生产模式下跳过 `.env`，`start:prod` 也不自动读取 `.env.production` |
| 后端 E2E | 测试准备与 Jest setup 显式加载 `.env.test`，保留已有进程变量；应用在 `NODE_ENV=test` 下跳过开发 `.env`。入口要求数据库名以 `_test` 结尾，具体准备见[后端测试说明](../backend/TEST.md) |
| Python 独立服务 | 使用自身启动脚本与配置；扩展参数见[嵌入服务示例](../backend/python-embedding-service/env.example)。生产 Compose 仅注入本页列明的模型参数与 `HF_ENDPOINT` |

生产 Compose 中，可选字段省略后保持容器环境缺省，应用继续使用默认值。显式 `NAME=` 会把空字符串传入容器，具体效果由消费者决定：登录方式空值关闭全部渠道，空 `DATABASE_URL` 会报错。含 `${NAME:-默认值}` 的 Compose 字段则在省略或为空时使用编排默认值。

| 角色 | 共享与专属配置 |
|---|---|
| `public-api` | 数据库、Redis、嵌入、审核、新闻采集、存储；JWT、来源、上传限制；用户登录、校园认证、AI；通知 webhook URL |
| `admin-api` | 数据库、Redis、嵌入、审核、新闻采集、存储；JWT、来源、上传限制；通知 webhook URL |
| `worker` | 数据库、Redis、嵌入、审核、新闻采集、存储；通知 webhook URL、签名密钥与投递调优 |
| `migrate` | 数据库、生产安全开关、首次管理员凭据；执行迁移和初始化后退出 |
| `nginx` | 两个公网 origin、TLS、入口端口与证书挂载、可选 WeRSS 代理地址；通过共享上传卷提供公开图片 |
| `werss` | 独立登录账号、会话签名密钥、采集模式与面板地址；通过独立数据卷保存订阅和授权 |
| `embedding-service` | 文本模型、默认版本、设备、预热版本和模型下载源 |

本文各节标明消费角色。完整 Compose 解析时仍会检查编排中的全部必填插值，即使命令只选取一个服务；直接运行独立 `migrate` 入口只需要迁移角色的参数。

## 基础连接与首次初始化

数据库参数供四个后端角色消费；Redis 参数供两个 API 和 worker 消费。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `NODE_ENV` | 接受 `development`、`test`、`production`，缺省 `development`；决定加载方式和生产校验。开发命令与生产镜像各自固定相应模式 |
| `POSTGRES_USER` | 数据库用户名；通过原始参数生成连接串时必填，完整 Compose 也要求提供给内置 PostgreSQL |
| `POSTGRES_PASSWORD` | 原始数据库口令；必填条件同上。直接填写原始字符，连接解析器负责 URL 编码；生产须替换占位口令 |
| `POSTGRES_DB` | 数据库名；必填条件同上。开发模板 `tasteinsight_dev`，生产模板 `tasteinsight`；E2E 库名要求 `_test` 后缀 |
| `POSTGRES_HOST` | 主机名或 IP；解析器默认 `localhost`，生产 Compose 默认 `db`，开发模板 `localhost` |
| `POSTGRES_PORT` | 整数 `1–65535`；解析器和生产 Compose 默认 `5432`，开发模板 `5434`。本地 Compose 同时用它设置宿主机映射端口 |
| `POSTGRES_SSLMODE` | 仅生成连接串时使用，可选 `disable`、`prefer`、`require`；省略时不添加 `sslmode` 参数 |
| `DATABASE_URL` | 可选完整 PostgreSQL URL，**显式设置时优先于全部 `POSTGRES_*` 应用连接参数**。空字符串报错；保留自定义查询参数；URL 内的账号、密码和库名需自行编码 |
| `REDIS_HOST` | Redis 主机；代码默认 `localhost`，生产 Compose 默认 `redis`；生产常驻角色必填 |
| `REDIS_PORT` | 整数 `1–65535`，代码及生产 Compose 默认 `6379`，开发模板 `6380`；本地 Compose 同时用它设置宿主机映射端口 |
| `REDIS_PASSWORD` | Redis 口令；生产常驻角色和两种 Compose 的 Redis 服务必填，生产须替换占位口令 |
| `REDIS_REC_DB` | 推荐缓存使用的 Redis 逻辑库，默认 `1`，取非负整数；与其他 Redis 用途区分 |
| `INITIAL_ADMIN_USERNAME` | 首次管理员用户名，缺省无值；`migrate` 和开发合并入口初始化时使用 |
| `INITIAL_ADMIN_PASSWORD` | 首次管理员密码，缺省无值；生产提供时至少 12 字符，并通过占位值、明显默认值检查 |

`DATABASE_URL` 只覆盖应用连接，完整 Compose 仍要求 `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB` 来解析数据库服务。连接外部实例的编排方式见[独立数据库、Redis 与嵌入服务](环境配置与部署.md#独立数据库redis-与嵌入服务)。修改 PostgreSQL 环境凭据只影响新建数据库初始化，已有数据卷的账号需单独管理。

宿主机开发的连接示例：

```dotenv
POSTGRES_HOST=localhost
POSTGRES_PORT=5434
POSTGRES_USER=tasteinsight
POSTGRES_PASSWORD=<开发数据库口令>
POSTGRES_DB=tasteinsight_dev
REDIS_HOST=localhost
REDIS_PORT=6380
REDIS_PASSWORD=<开发Redis口令>
# REDIS_REC_DB=1
```

外部 PostgreSQL 可选用原始参数加 TLS，或使用完整连接串。以下两项展示后者的覆盖入口：

```dotenv
# POSTGRES_SSLMODE=require
# DATABASE_URL=postgresql://app:<经过URL编码的口令>@database.example.invalid:5432/tasteinsight?schema=public&sslmode=require
```

全新数据库需同时设置首次管理员两项；已有管理员时初始化保持原账号与密码。初始化完成后移除环境中的初始密码。

```dotenv
# INITIAL_ADMIN_USERNAME=admin
# INITIAL_ADMIN_PASSWORD=<至少12字符的独立初始密码>
```

Redis 当前按地址、端口和口令建立 TCP 连接；托管产品的 TLS、集群协议与网络要求需按实际客户端支持验收。

## API、JWT 与代理

本节参数供两个 API 消费；`PORT` 也用于 worker 的内部健康检查服务。生产 Compose 将三个常驻角色的 `PORT` 固定为 `3000`。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `PORT` | HTTP 监听端口，整数 `1–65535`，代码默认 `3000`，宿主机开发模板 `3001` |
| `APP_URL` | 公共用户 API 地址；独立生产 API 必填。完整 Compose 和网关要求 HTTP(S) origin，例如 `https://api.example.com`，路径、查询和凭据应留空；开发模板 `http://localhost:3001` |
| `ADMIN_APP_URL` | 管理站点 origin；完整 Compose 必填，并与 `APP_URL` 使用不同 DNS 主机名。独立 API 可选；提供时加入 CORS 允许列表。开发模板 `http://localhost:5173` |
| `JWT_SECRET` | Access Token 签名密钥，API 签发与验证时需要；生产至少 32 字节，使用独立随机值 |
| `JWT_REFRESH_SECRET` | Refresh Token 签名密钥，条件同上；生产要求与 `JWT_SECRET` 不同 |
| `JWT_EXPIRATION_TIME` | Access Token 有效期，默认 `3600` 秒；纯数字按秒，带单位支持 `ms/s/m/h/d/w/y`，如 `3600s`、`1h` |
| `JWT_REFRESH_EXPIRATION_TIME` | Refresh Token 有效期，默认 `604800` 秒；格式同上，如 `7d` |
| `CORS_ALLOWED_ORIGINS` | 逗号分隔的精确 HTTP(S) origin，缺省为空；支持端口，路径、通配符、凭据、查询和片段均会校验失败。`APP_URL` 与 `ADMIN_APP_URL` 的 origin 自动加入 |
| `TRUSTED_PROXY_CIDRS` | 逗号分隔的可信代理 IP 或 CIDR，缺省忽略转发客户端 IP 的头。填写应用实际经过的代理地址，限制信任范围 |

开发浏览器与 JWT 时长示例：

```dotenv
# JWT_EXPIRATION_TIME=3600s
# JWT_REFRESH_EXPIRATION_TIME=7d
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://localhost:5174
# TRUSTED_PROXY_CIDRS=172.20.0.2/32
```

无 `Origin` 的原生与小程序请求可以到达 API，业务接口继续执行 Bearer JWT 鉴权。浏览器跨域策略的 `credentials` 为 `false`。公网域名、入口端口、TLS 组合见[容器、网关与镜像](#容器网关与镜像)。

## 登录与校园身份认证

本节仅注入 `public-api`；小程序凭据还供两个 API 和 worker 的内容审核共用。渠道开关与凭据共同决定能力接口的可用状态。

### 渠道开关与微信身份

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `AUTH_LOGIN_METHODS` | 登录渠道白名单，逗号分隔 `phone`、`wechatMiniapp`、`wechatApp`、`campusOAuth`。默认 `wechatMiniapp,wechatApp`；空字符串关闭全部登录渠道，手机号需显式启用 |
| `CAMPUS_VERIFICATION_METHODS` | 校园资格认证白名单，逗号分隔 `campusEmail`、`campusOAuth`。默认两种均启用；空字符串关闭全部认证渠道及登录后的自动校园认证 |
| `WECHAT_APPID` | 微信小程序 AppID，与 `WECHAT_SECRET` 成对提供；用于小程序登录、取得审核 access token 和定位当前小程序下的用户 OpenID，无默认值 |
| `WECHAT_SECRET` | 同一小程序的 AppSecret，与 AppID 成对提供，无默认值 |
| `WECHAT_APP_APPID` | 原生 Android/iOS 微信应用 AppID，与 `WECHAT_APP_SECRET` 成对提供，无默认值 |
| `WECHAT_APP_SECRET` | 同一原生应用的 Secret，无默认值 |
| `WECHAT_OPEN_PLATFORM_ID` | 微信开放平台账号的稳定命名空间，无默认值；用于同一开放平台下小程序与原生应用的 UnionID 关联，需在这些应用间保持一致 |

仅使用小程序登录的配置示例；按实际需求独立选择校园认证渠道：

```dotenv
AUTH_LOGIN_METHODS=wechatMiniapp
CAMPUS_VERIFICATION_METHODS=campusEmail,campusOAuth
WECHAT_APPID=<微信小程序AppID>
WECHAT_SECRET=<微信小程序AppSecret>
# WECHAT_APP_APPID=<微信原生应用AppID>
# WECHAT_APP_SECRET=<微信原生应用Secret>
# WECHAT_OPEN_PLATFORM_ID=<同一开放平台账号的稳定标识>
```

校园登录凭据与校园资格各有用途：`AUTH_LOGIN_METHODS` 控制登录及登录方式绑定，`CAMPUS_VERIFICATION_METHODS` 控制资格认证。认证记录保存在 `StudentVerification`，登录凭据保存在 `UserIdentity`；认证入口只更新校园资格，绑定入口只更新登录凭据。关闭认证渠道后，已有资格继续按审核状态和有效期生效。

### 短信与校园邮箱

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `AUTH_CHALLENGE_SECRET` | 短信、邮箱、校园 OAuth 的验证码与一次性挑战使用的独立密钥；配置上述任一集成时必填，至少 32 字节，须替换占位值；无默认值 |
| `SMS_GATEWAY_URL` | 短信网关 HTTPS URL；启用手机号登录时与 Token、挑战密钥一并配置，无默认值 |
| `SMS_GATEWAY_TOKEN` | 短信网关 Bearer Token；与 URL 成对必填，无默认值 |
| `RESEND_API_KEY` | Resend 邮件 API 密钥；与发件人、校园域名、挑战密钥一并配置，无默认值 |
| `EMAIL_FROM` | Resend 已验证域名下的发件人；与 API Key 成对必填，无默认值 |
| `CAMPUS_EMAIL_DOMAINS` | 精确校园邮箱域名，逗号分隔，如 `student.example.edu,example.edu`；启用邮件时必填，无默认值，按完整域名匹配 |

```dotenv
# AUTH_CHALLENGE_SECRET=<至少32字节的独立随机密钥>
# SMS_GATEWAY_URL=https://sms.example.invalid/send
# SMS_GATEWAY_TOKEN=<短信网关Token>
# RESEND_API_KEY=<Resend API密钥>
# EMAIL_FROM=TasteInsight <no-reply@example.edu>
# CAMPUS_EMAIL_DOMAINS=student.example.edu,example.edu
```

短信网关接收 HTTPS POST JSON `{to, code, expiresIn, purpose}`，请求使用 Bearer Token，成功响应包含 `{messageId: "投递编号"}`。校园邮箱验证证明邮箱持有权并生成待审核申请，管理员通过后授予校园资格。

### 校园 OAuth

向校方接入方取得端点、scope、issuer 和声明字段。以下八项为一组：授权 URL、令牌 URL、用户信息 URL、Client ID、Client Secret、回调 URI、scope、issuer；配置任一项时启动校验要求全部提供，同时配置 `AUTH_CHALLENGE_SECRET`。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `CAMPUS_OAUTH_AUTHORIZATION_URL` | 校方授权端点，HTTPS URL，无默认值，属于必填组 |
| `CAMPUS_OAUTH_TOKEN_URL` | 授权码换取令牌端点，HTTPS URL，无默认值，属于必填组 |
| `CAMPUS_OAUTH_USERINFO_URL` | 获取可信账号和在读声明的端点，HTTPS URL，无默认值，属于必填组 |
| `CAMPUS_OAUTH_CLIENT_ID` | 校方分配的客户端 ID，无默认值，属于必填组 |
| `CAMPUS_OAUTH_CLIENT_SECRET` | 对应客户端密钥，无默认值，属于必填组 |
| `CAMPUS_OAUTH_REDIRECT_URI` | 已向校方登记的固定后端 HTTPS 回调 URL，无默认值，属于必填组；使用公共 API 的 `/user/student-verification/oauth/callback` 路由并包含实际公网 API 前缀 |
| `CAMPUS_OAUTH_SCOPE` | 校方批准的授权范围字符串，无默认值，属于必填组 |
| `CAMPUS_OAUTH_ISSUER` | 校方身份发行方标识，要求 HTTPS URL，无默认值，属于必填组；参与身份唯一性与返回 issuer 检查 |
| `CAMPUS_OAUTH_SUBJECT_CLAIM` | 账号唯一标识的声明路径，默认 `sub`；支持以点分隔的嵌套路径 |
| `CAMPUS_OAUTH_STUDENT_CLAIM` | 可信在读状态声明路径，无默认值；与允许值成对提供 |
| `CAMPUS_OAUTH_STUDENT_VALUES` | 在读状态允许值，逗号分隔，无默认值；声明为字符串、数字、布尔值或数组时，按元素字符串值匹配 |
| `CAMPUS_OAUTH_TOKEN_AUTH_METHOD` | 换取令牌时的客户端认证方式，默认 `client_secret_basic`；可选 `client_secret_post` |
| `CAMPUS_VERIFICATION_DAYS` | 可信在读资格的有效天数，默认 `30`，整数 `1–366` |

生产网关的回调配置示例：

```dotenv
# CAMPUS_OAUTH_AUTHORIZATION_URL=https://sso.example.edu/oauth/authorize
# CAMPUS_OAUTH_TOKEN_URL=https://sso.example.edu/oauth/token
# CAMPUS_OAUTH_USERINFO_URL=https://sso.example.edu/oauth/userinfo
# CAMPUS_OAUTH_CLIENT_ID=<校方分配的Client ID>
# CAMPUS_OAUTH_CLIENT_SECRET=<校方分配的Client Secret>
# CAMPUS_OAUTH_REDIRECT_URI=https://api.example.com/api/v1/user/student-verification/oauth/callback
# CAMPUS_OAUTH_SCOPE=openid profile
# CAMPUS_OAUTH_ISSUER=https://sso.example.edu
# CAMPUS_OAUTH_SUBJECT_CLAIM=sub
# CAMPUS_OAUTH_STUDENT_CLAIM=affiliation
# CAMPUS_OAUTH_STUDENT_VALUES=student
# CAMPUS_OAUTH_TOKEN_AUTH_METHOD=client_secret_basic
# CAMPUS_VERIFICATION_DAYS=30
```

示例中的 `scope`、issuer 和声明字段需按校方实际协议替换。在读声明缺失或未匹配时进入待审核状态；OAuth 登录流程仅在校园 OAuth 认证渠道也开启时更新校园资格。所有 OAuth URL 均要求 HTTPS，并禁止 URL 凭据与片段。

## 统一内容审核

审核配置分为管理端策略和服务端凭据。管理端“系统配置 → 审核设置 → 统一内容审核”将 `enabled`、`provider`、`mode` 保存在数据库；缺省策略为关闭、阿里云、机器审核。服务商支持 `aliyun` 和 `wechat`；方式支持 `manual`、`machine`、`machine_and_manual`。策略更新用于新任务，已有任务沿用提交时保存的策略。

环境变量供 `public-api`、`admin-api`、`worker` 共用。修改凭据、图片根地址或存储位置后，重新创建这三个角色；管理端保存策略后，新任务直接采用新的设置。

### 私有图片签名与访问地址

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `MODERATION_MEDIA_SECRET` | **本项目私有审核图片的 HMAC 签名密钥**，无默认值；统一审核开启时必填，至少 32 字符，人工审核同样要求。使用独立随机值，与 JWT、微信 Token/AESKey 分开管理 |
| `MODERATION_PUBLIC_BASE_URL` | **本项目公共 API 根地址**，用于拼接审核图片 URL，并作为微信回调 URL 的配置基准；无默认值。统一审核开启时必填，支持 HTTP(S)，生产要求 HTTPS；禁止凭据、查询和片段。应包含实际公网 API 前缀 |

宿主机开发示例：

```dotenv
MODERATION_MEDIA_SECRET=<至少32字符的独立随机图片签名密钥>
MODERATION_PUBLIC_BASE_URL=http://localhost:3001
```

生产网关使用 `MODERATION_PUBLIC_BASE_URL=https://api.example.com/api/v1`，`APP_URL` 仍为 `https://api.example.com`。系统据此生成 `/content-moderation/images/:id` 的限时签名地址，供检测服务下载和管理员预览。密钥可用 `openssl rand -hex 32` 生成。

当前统一审核在启用时整体检查上述两项，覆盖人工和机器模式。该要求来自本项目私有图片流程与管理端就绪校验；微信 `msg_sec_check` 文本请求的参数见下节。

### 微信文本、图片与回调

| 配置层 | 使用内容 |

| 取得服务端 access token | `WECHAT_APPID` 与 `WECHAT_SECRET`，对应同一微信小程序；后端调用稳定版令牌接口并缓存令牌 |

## 上传存储

两个 API 和 worker 使用同一存储类型、存储位置与访问凭据。`local` 使用共享目录；`oss` 使用阿里云原生 SDK；`s3` 使用 AWS SDK for JavaScript v3 访问 AWS S3、腾讯云 COS 和兼容 S3 的服务。普通上传、审核图片和贡献图片清理使用同一存储适配器。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `UPLOAD_STORAGE_TYPE` | 上传策略，默认 `local`，接受 `local`、`oss`、`s3`；显式空字符串会校验失败 |
| `UPLOAD_LOCAL_PATH` | 本地目录，代码默认 `./uploads`，开发模板 `./uploads-dev`。生产 Compose 固定 `/app/uploads` 并共享 `uploads_data` 卷 |
| `UPLOAD_BASE_URL` | 本地公开图片 URL 前缀，默认 `${APP_URL}/images`；`APP_URL` 缺省时基于 `http://localhost:3000` |
| `UPLOAD_MAX_FILE_SIZE` | API 上传大小上限，单位字节，默认 `10485760`（10 MiB），取正整数 |
| `OSS_REGION` | OSS 地域，例如 `oss-cn-shanghai`；使用 `oss` 时必填 |
| `OSS_ACCESS_KEY_ID` | OSS AccessKey ID；使用 `oss` 时必填 |
| `OSS_ACCESS_KEY_SECRET` | OSS AccessKey Secret；使用 `oss` 时必填 |
| `OSS_BUCKET` | OSS Bucket 名；使用 `oss` 时必填 |
| `OSS_CUSTOM_DOMAIN` | OSS 公共对象的自定义 URL 域名前缀，可选；省略时采用 OSS 返回的 URL |
| `S3_ENDPOINT` | S3 API 的完整 HTTP(S) 服务地址，使用 `s3` 时必填。填写服务级地址，Bucket 通过 `S3_BUCKET` 提供；支持服务路径前缀 |
| `S3_REGION` | 签名地域，使用 `s3` 时必填；COS 示例 `ap-guangzhou`，AWS 示例 `ap-southeast-1` |
| `S3_BUCKET` | 存储桶名，使用 `s3` 时必填；COS 使用包含 APPID 的完整名称，例如 `photos-1250000000` |
| `S3_ACCESS_KEY_ID` | S3 Access Key ID；COS 对应 SecretId，使用 `s3` 时必填 |
| `S3_SECRET_ACCESS_KEY` | S3 Secret Access Key；COS 对应 SecretKey，使用 `s3` 时必填 |
| `S3_SESSION_TOKEN` | 临时凭据的会话令牌，可选。临时凭据到期前更新整组凭据并重新创建三个进程 |
| `S3_FORCE_PATH_STYLE` | `true` 或 `false`，默认 `false`，采用虚拟主机寻址。MinIO 等本地服务通常设置 `true` |
| `S3_PUBLIC_BASE_URL` | 公共图片 URL 前缀，可含路径，例如 `https://images.example.com/media`。省略时采用 SDK 根据 endpoint、Bucket 和寻址方式生成的对象地址；用于普通图片返回 URL |

```dotenv

# UPLOAD_MAX_FILE_SIZE=10485760
```

```dotenv

# OSS_BUCKET=<Bucket名>

```


### 图片权限与生命周期

普通云端图片保存于 `images/`，审核暂存图片保存于 `moderation-private/`。本地审核图片位于 `.moderation/`。审核 API 对待审核图片验证限时签名，审核通过后由同一 API 提供公开访问；云端暂存对象持续保持私有。

S3 桶创建为私有，按前缀向匿名用户授予 `images/*` 的 `GetObject` 权限。`moderation-private/*` 保持仅服务端身份可读，并让 CDN、代理沿用该访问范围。S3 适配器采用桶策略控制访问，可用于 AWS 的 Bucket owner enforced 模式。服务端身份需要对两个前缀具有 `PutObject`、`GetObject`、`DeleteObject` 权限；配置 COS 的 CAM 策略时采用对应的 COS action 与资源格式。

AWS S3 和 MinIO 的公共图片策略示例，替换 `photos` 为实际桶名：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicImages",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::photos/images/*"
    }
  ]
}
```

AWS 的 Block Public Access 设置需与公共前缀策略相容；采用私有 CDN 源站时，可将公开访问授权配置在 CDN 身份上。OSS 暂存对象继续使用私有 ACL，并维持对应前缀的访问限制。上传数据登记失败时删除已上传对象；过期且未绑定提交的贡献图片由 worker 清理，删除失败后重试。

变更存储类型、endpoint 或 Bucket 前，迁移原图片、审核资产和贡献图片记录，并核对 `storageType`、`storageKey` 与已保存 URL。三个进程使用一致配置后再恢复上传和清理；存储类型变更后的旧审核记录会报告配置变化，清理仅扫描当前类型。相同类型下更换 Bucket 也需要完成资产迁移。

### 存储验收

1. 重建 `public-api`、`admin-api` 和 `worker`，确认采用相同的存储参数。
2. 上传普通图片，确认返回 URL 可从浏览器访问、MIME 与实际图片一致。
3. 启用人工审核并上传图片，确认签名 URL 可读，缺少签名或签名到期时受限，直接访问存储/CDN 的 `moderation-private/` 对象受限。
4. 审核通过后通过审核图片 API 读取图片，确认源对象继续私有。
5. 使用隔离测试记录验证登记失败回滚、过期贡献图片清理、删除失败重试，并核对桶中实际对象。

跨主机部署时，为 API 和 worker 提供同一存储位置；单机命名卷范围见[部署边界](环境配置与部署.md#可选嵌入服务与独立部署边界)。业务媒体桶的版本保护与备份独立配置，运维 `BACKUP_S3_*` 参数用于 restic 备份仓库。

## 公众号新闻采集

API 与 worker 共享 WeRSS 连接配置。服务地址、AK、SK 三项齐全时，管理端显示“公众号来源”，后台启用定时导入。浏览器面板通过 Vite 或管理域名 Nginx 的 `/werss/` 代理访问，独立 WeRSS 使用其实际面板地址。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `WERSS_BASE_URL` | 后端可访问的服务根地址；同机容器为 `http://werss:8001`，宿主机开发为 `http://127.0.0.1:8001` |
| `WERSS_ADMIN_URL` | 浏览器可访问的 HTTP(S) 面板地址；省略时使用 `ADMIN_APP_URL/werss/`。显式独立面板地址会关闭管理域名下的同路径代理 |
| `WERSS_ACCESS_KEY` / `WERSS_SECRET_KEY` | 在 WeRSS 面板创建的 AK/SK，仅供后端访问；与独立面板登录账号分别配置 |
| `WERSS_USERNAME` / `WERSS_PASSWORD` | 同机采集容器的初始管理员，用户名默认 `admin`；密码启动时必填。已有用户沿用数据卷中的密码，通过面板修改 |
| `WERSS_SESSION_SECRET` | 同机采集容器的会话签名密钥，启动时必填；可用 `openssl rand -hex 32` 生成 |
| `WERSS_PORT` | 同机采集容器的宿主机回环端口，默认 `8001`，用于根路径 API 排障 |
| `WERSS_GATHER_MODEL` | 采集模式，默认 `weread_mp`；采集范围与授权由 WeRSS 决定 |
| `WERSS_IMAGE` | 兼容 `/werss/` 的配套镜像覆盖；默认 `${IMAGE_REGISTRY}/tasteinsight-werss:${TAG}` |

同机容器示例：

```dotenv
# COMPOSE_PROFILES=werss
# WERSS_BASE_URL=http://werss:8001
# WERSS_ADMIN_URL=https://admin.example.com/werss/
# WERSS_ACCESS_KEY=<WeRSS API key>
# WERSS_SECRET_KEY=<WeRSS API secret>
# WERSS_USERNAME=admin
# WERSS_PASSWORD=<独立的 WeRSS 登录密码>
# WERSS_SESSION_SECRET=<随机会话签名密钥>
# WERSS_PORT=8001
# WERSS_GATHER_MODEL=weread_mp
# WERSS_IMAGE=ghcr.io/tasteinsight/tasteinsight-werss:<release-tag>
```

`COMPOSE_PROFILES` 按需填写 `werss` 或 `embedding,werss`，同一文件保留一条配置。首次先启动完整服务栈与网关，通过管理域名授权并创建 AK/SK，再重建 API 和 worker 加载密钥。

宿主机开发在 `frontend-web/.env.development.local` 配置开发代理，端口与本机 WeRSS 映射一致；`WERSS_PROXY_TARGET` 仅由 Vite 开发服务器消费：

```dotenv
# WERSS_PROXY_TARGET=http://127.0.0.1:8001
```

完整启用、外部服务接入、草稿与自动发布、停用和备份步骤见[微信公众号新闻同步](微信公众号新闻同步.md)。

## AI 对话

仅 `public-api` 消费。每个字段按**非空环境值 → 数据库配置 → 代码默认值**独立取值；省略或空值允许管理端保存的数据库配置生效。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `AI_PROVIDER` | 对话服务商，默认 `openai`，当前支持此值，比较前转为小写；其他名称在调用时失败 |
| `AI_API_KEY` | 模型 API 密钥，环境与数据库均无值时为空；实际调用需要有效凭据 |
| `AI_MODEL` | 模型名称，默认 `gpt-4o-mini`；填写时覆盖数据库中的 `ai.model` |
| `AI_BASE_URL` | 自定义 OpenAI 兼容端点，默认交由 SDK；填写时覆盖数据库中的 `ai.base_url` |

```dotenv
# AI_PROVIDER=openai
# AI_API_KEY=<模型API密钥>
# AI_MODEL=<目标服务支持的模型名>
# AI_BASE_URL=https://ai.example.invalid/v1
```

## 容器、网关与镜像

本节由 Compose、网关或部署命令消费，通常加入生产私有 env 文件。应用连接参数见前文；完整单机编排通过内部服务名通信，网关发布站点端口，可选 WeRSS 另有回环排障端口。

| 变量 | 用途、必填条件与默认值 |
|---|---|
| `COMPOSE_PROJECT_NAME` | Compose 项目名，决定网络与命名卷前缀；生产模板 `tasteinsight-production`，本地基础设施编排名为 `tasteinsight-dev`。已有部署沿用原项目名；命令行 `-p` 优先 |
| `COMPOSE_PROFILES` | 逗号分隔的 Compose profile；默认关闭可选容器，`embedding` 启用同机 Python 服务，`werss` 启用公众号采集，两者同开填写 `embedding,werss`；外部基础设施覆盖使用的 `local-db` / `local-redis` 见部署文档 |
| `IMAGE_REGISTRY` | 镜像仓库前缀，默认 `ghcr.io/tasteinsight`；用于拼接后端、前端、嵌入和 WeRSS 镜像名 |
| `TAG` | 上述镜像的共同标签，默认 `latest`；发布流程可注入不可变版本标签 |
| `NGINX_IMAGE` | 网关镜像，默认 `nginx:1.28-alpine`；所选版本需支持当前动态 upstream DNS 配置，至少 Nginx `1.27.3` |
| `GATEWAY_BIND_HOST` | 网关宿主机监听地址，默认 `0.0.0.0`；仅限本机访问时可选 `127.0.0.1` |
| `HTTP_PORT` | 网关宿主机 HTTP 端口，Compose 默认 `8080`，生产模板 `80` |
| `HTTPS_PORT` | 网关宿主机 TLS 端口，Compose 默认 `8443`，生产模板 `443`；与 origin 中的非标准端口保持一致 |
| `GATEWAY_TLS_MODE` | 网关 TLS 模式，默认 `off`，生产模板 `on`。`on` 时两个 origin 均使用 HTTPS，`off` 可用于本地 HTTP 或外部代理终止 TLS |
| `TLS_CERTS_PATH` | 宿主机证书目录，默认 `./certs`，只读挂至 `/etc/nginx/tls`；网关直接终止 TLS 时准备两个域名的证书 |
| `TLS_CERT_FILE` | 证书目录内的证书链文件名，默认 `fullchain.pem` |
| `TLS_KEY_FILE` | 证书目录内的私钥文件名，默认 `private.key` |
| `WORKER_STOP_GRACE_PERIOD` | worker 优雅退出时限，默认 `90s`，使用 Compose 时长格式，如 `60s`、`1m30s` |
| `POSTGRES_EXPOSE_PORT` | 旧本地 PostgreSQL 映射端口；仅在 `POSTGRES_PORT` 缺省或为空时回退使用，再缺省为 `5434`。新开发配置直接设置 `POSTGRES_PORT` |
| `REDIS_EXPOSE_PORT` | 旧本地 Redis 映射端口；仅在 `REDIS_PORT` 缺省或为空时回退使用，再缺省为 `6380`。新开发配置直接设置 `REDIS_PORT` |

直接终止 HTTPS 的主要配置示例：

```dotenv
APP_URL=https://api.example.com
ADMIN_APP_URL=https://admin.example.com
GATEWAY_TLS_MODE=on
HTTP_PORT=80
HTTPS_PORT=443
TLS_CERTS_PATH=./certs
# TLS_CERT_FILE=fullchain.pem
# TLS_KEY_FILE=private.key
# GATEWAY_BIND_HOST=0.0.0.0
```

镜像与可选服务覆盖：

```dotenv
# COMPOSE_PROFILES=embedding
# IMAGE_REGISTRY=ghcr.io/tasteinsight
# TAG=latest
# NGINX_IMAGE=nginx:1.28-alpine
# WORKER_STOP_GRACE_PERIOD=90s
```

网关 origin 的 Host、TLS 证书、反向代理信任范围和外部基础设施拓扑需协同配置，参见[HTTPS 与外部反向代理](环境配置与部署.md#https-与外部反向代理)。运维工具参数见 [ops](../ops/README.md)，压测参数见 [perf](../perf/README.md)。

## 开发与测试开关

所有后端角色均校验以下三项，默认 `false`；布尔值接受 `true`、`false`，省略或空值按 `false` 处理。

| 变量 | 用途与生效范围 |
|---|---|
| `ENABLE_MOCK_AUTH` | 开发和隔离测试的模拟身份入口，需同时满足 `NODE_ENV=development` 或 `test`；生产启用时启动失败。前端测试登录还有独立开关，见部署文档 |
| `RUN_SEED` | 保留的旧启动开关，当前入口仅解析并执行生产安全校验；初始化由独立迁移/初始化流程负责。生产启用时启动失败 |
| `IMPORT_DATA` | 保留的旧启动开关，当前入口仅解析并执行生产安全校验；维护导入使用显式 `maintenance:import` 命令。生产启用时启动失败 |

```dotenv
# ENABLE_MOCK_AUTH=false
# RUN_SEED=false
# IMPORT_DATA=false
```

E2E 的数据库、Redis、上传路径与测试密钥从 `.env.test.example` 单独准备；启动测试前核对 `_test` 数据库目标。测试准备会迁移并重建测试数据，步骤与隔离规则见[后端测试说明](../backend/TEST.md)。
