# 环境配置与部署

本文档是 TasteInsight 开发、生产部署和冷启动配置的唯一说明。各子项目 README 只保留常用命令。

## 配置原则

| 范围 | 开发环境 | 生产环境 |
|---|---|---|
| 后端运行变量 | `backend/.env`，由 `.env.example` 复制 | `backend/.env.production`，由 `.env.production.example` 复制 |
| Compose 文件 | `backend/docker-compose.local.yml`，仅数据库和 Redis | `backend/docker-compose.yml`，完整服务 |
| 后端端口 | `3001` | 容器内固定 `3000`，公网入口由 `HTTP_PORT` 控制 |
| PostgreSQL | `localhost:${POSTGRES_EXPOSE_PORT}`，默认 `5434` | 后端容器连接 `db:5432`，不映射宿主机端口 |
| Redis | `localhost:${REDIS_EXPOSE_PORT}`，默认 `6380` | 后端容器连接 `redis:6379`，不映射宿主机端口 |
| 管理端 API | `.env.development`：`http://localhost:3001` | `.env.production`：相对路径 `/api/v1` |
| 小程序 API | `.env.development`：`http://localhost:3001` | 构建时提供 HTTPS 请求域名，或填写被忽略的 `.env.production` |

后端密钥、数据库口令等放在被 Git 忽略的 `.env`、`.env.production` 或 `.env.test`。本地 E2E 测试使用独立数据库，配置和准备步骤见 [后端测试说明](../backend/TEST.md)。`VITE_*` 会被打进前端产物，只能存放公开配置，不能存放密钥。

本地 Nest 进程读取 `backend/.env`，本地 Compose 从同一文件取得 PostgreSQL 和 Redis 参数。生产 Compose 使用 `--env-file .env.production` 解析数据库变量，后端容器通过固定的 `env_file: .env.production` 读取应用配置。生产容器内的 `NODE_ENV`、`PORT` 和 Redis 地址由 Compose 指定；后端入口脚本始终根据原始 PostgreSQL 凭证生成经过 URL 编码的 `DATABASE_URL`。Python 嵌入容器只接收 Compose 明确列出的 `PYTHON_EMBEDDING_*` 和 `HF_ENDPOINT` 变量。

对话服务支持 `AI_PROVIDER=openai`。`AI_PROVIDER`、`AI_API_KEY`、`AI_MODEL`、`AI_BASE_URL` 按环境变量、数据库配置、代码默认值的顺序取值。模板中的 `AI_MODEL` 留空，允许管理端数据库配置生效；未设置时使用 `gpt-4o-mini`。其他 provider 名称会在发起对话前报错。

宿主机映射端口与容器内端口是两组变量：

- 本地后端连接 Redis 使用 `REDIS_HOST`、`REDIS_PORT`，本地 Compose 的宿主机端口由 `REDIS_EXPOSE_PORT` 控制。
- 本地后端连接数据库使用完整的 `DATABASE_URL`；本地 Compose 的宿主机端口由 `POSTGRES_EXPOSE_PORT` 控制。
- 后端监听端口由 `PORT` 指定。

## 本地开发

### 1. 启动 PostgreSQL 和 Redis

项目需要带 pgvector 扩展的 PostgreSQL。本地 Compose 只定义数据库和 Redis：

```bash
cd backend
cp .env.example .env
# 编辑 .env，至少替换 PostgreSQL、Redis、JWT 和初始管理员密码
docker compose -f docker-compose.local.yml up -d
```

默认只绑定宿主机回环地址：PostgreSQL `127.0.0.1:5434`，Redis `127.0.0.1:6380`。修改 `.env` 中的 `POSTGRES_EXPOSE_PORT` 或数据库账号、密码后，同步修改完整的 `DATABASE_URL`；修改 `REDIS_EXPOSE_PORT` 后，同步修改 `REDIS_PORT`。

本地 Compose 项目名为 `tasteinsight-dev`，数据库和 Redis 使用独立数据卷。生产 Compose 保留目录默认项目名；从 `backend/` 运行时为 `backend`，现有生产数据卷名称保持不变。切换 Compose 文件不会迁移或删除现有数据卷；已有数据库可通过 `.env` 中的 `DATABASE_URL` 直接连接。

如果已有 pgvector PostgreSQL 和 Redis，直接在 `.env` 中填写连接信息。

### 2. 初始化并启动后端

```bash
cd backend
pnpm install
pnpm exec prisma generate
pnpm exec prisma migrate deploy
pnpm run start:dev
```

后端默认监听 `http://localhost:3001`。源码启动不会自动执行迁移，因此首次启动和拉取新迁移后必须显式运行 `prisma migrate deploy`。

默认 `EXTERNAL_EMBEDDING_SERVICE_ENABLED=false`，推荐功能使用内置 v1 嵌入，不需要另起 Python 服务。如需本地使用 Python v2/v3 嵌入，将该开关改为 `true`，再开一个终端执行 `pnpm run start:embedding`；该命令会把同一份 `backend/.env` 显式注入 Python 进程。

### 3. 启动管理端

```bash
cd frontend-web
pnpm install
pnpm dev
```

访问 `http://localhost:5173`。开发模式自动读取 `.env.development`，请求 `http://localhost:3001`。机器专属覆盖写入被忽略的 `.env.development.local`。

### 4. 启动小程序

```bash
cd frontend-miniapp
pnpm install
pnpm dev:mp-weixin
```

微信开发者工具打开 `frontend-miniapp/dist/dev/mp-weixin/`。开发者工具可使用 `http://localhost:3001`；真机联调需将 `.env.development.local` 改为局域网可访问地址，并在开发工具中按需关闭合法域名校验。

### 5. 构建小程序发布包

```bash
cd frontend-miniapp
cp .env.production.example .env.production
# 在 .env.production 中填写完整 HTTPS API 基址，包含 /api/v1
pnpm build:mp-weixin
```

构建环境也可直接提供 `VITE_API_BASE_URL`，其值优先于文件内容。该地址会写入小程序产物。

## Docker 生产部署

当前网关是纯 HTTP，因为仓库没有可用证书。全新部署：

```bash
cd backend
cp .env.production.example .env.production
# 替换全部 change-me 值，并填写公网 APP_URL
docker compose --env-file .env.production config
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production logs -f backend nginx
```

已有部署升级时，先从原有 `backend/.env` 整理 `.env.production`，保留 `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB`、`REDIS_PASSWORD`、JWT 密钥和公网 `APP_URL`。已有 PostgreSQL 数据卷不会因修改环境变量而更改内部账号或密码。补入 `HTTP_PORT=80`，并保持原有 Compose 项目名（包括通过 `COMPOSE_PROJECT_NAME` 或 `-p` 指定的名称），再执行 `docker compose --env-file .env.production config` 核对配置。

默认生产模板同样关闭外部嵌入，`embedding-service` 位于可选的 `embedding` profile 中，不会构建或启动。需要 v2/v3 时，在 `.env.production` 中同时设置 `EXTERNAL_EMBEDDING_SERVICE_ENABLED=true` 和 `COMPOSE_PROFILES=embedding`。Compose 会读取该 profile，并等待嵌入服务健康再启动后端。手动命令也可使用 `--profile embedding` 临时启用容器。

### 自动部署

GitHub Actions 的开发、生产部署分别使用 `DEV_ENV_FILE`、`PROD_ENV_FILE` Secret，其内容遵循 `backend/.env.production.example`。部署流程将配置保存到服务器的 `.env.production`，所有 Compose 命令显式使用同一文件。需要 Python 嵌入容器时，在对应 Secret 中同时启用上述两个嵌入设置。

同一次流水线的三个镜像使用包含提交 SHA 和运行 ID 的专属标签，部署命令使用该标签。重跑失败任务时沿用原标签，以复用已成功构建的镜像。构建和部署文件检出同一触发提交，手动选择部署环境不会改变镜像来源；`latest` 和 `latest-dev` 仅作为便于人工查阅的别名。

网关配置直接来自仓库的 `backend/nginx.conf`。当前 HTTP 部署不使用 `DEV_NGINX_CONF`、`PROD_NGINX_CONF` 或 SSL 证书 Secret；HTTPS 恢复步骤见下文。升级自动部署配置时应保留原数据库凭证、JWT 密钥及 Compose 项目名。

默认拓扑：

```text
浏览器 :80
  -> backend/nginx.conf（公网网关）
       /api/v1/* -> backend:3000/*
       /images/* -> uploads_data
       /*         -> frontend:80
                         -> frontend-web/nginx.conf（静态文件与 SPA 回退）
```

两个 Nginx 配置职责不同：

- `backend/nginx.conf` 是唯一公网入口，负责跨容器路由、上传图片和 SSE 代理。
- `frontend-web/nginx.conf` 只服务 Vite 产物、Vue Router 回退和静态资源缓存，不代理 API。

管理端生产构建使用相对 API 地址 `/api/v1`，因此必须通过公网网关访问。不要单独暴露前端容器作为完整生产服务。

生产 PostgreSQL 和 Redis 只在容器网络内开放。需要进入数据库时，从 `backend` 目录运行 `docker compose --env-file .env.production exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'`。

生产容器的上传目录固定为 `/app/uploads`，对应 `uploads_data` 数据卷和网关的 `/images/` 路径。本地源码运行可通过 `UPLOAD_LOCAL_PATH` 指定目录。

### HTTPS 状态

`backend/nginx.conf` 当前只监听 HTTP，Compose 不挂载 `certs/`，也不暴露 443，避免继续使用过期证书。`backend/nginx.https.conf.example` 仅是证书续签后的参考模板，不会自动生效。

微信小程序正式版要求合法 HTTPS 请求域名。当前网关仅提供 HTTP；证书续签并在微信公众平台配置域名前，无法发布正式版小程序。恢复 HTTPS 后应同时：

1. 基于 `nginx.https.conf.example` 恢复网关 TLS 和 443 映射。
2. 将后端 `APP_URL` 改为 `https://...`。
3. 将小程序 `.env.production` 的 `VITE_API_BASE_URL` 改为 `https://.../api/v1` 后重新构建。

## 冷启动与普通重启

全新数据库第一次运行 `docker compose --env-file .env.production up -d --build` 时：

1. PostgreSQL 和 Redis 先通过健康检查；默认不启动可选的 Python 嵌入服务。
2. 后端入口脚本自动执行 `prisma migrate deploy`。
3. `RUN_SEED=false`，不会灌入或删除业务数据。
4. 管理员表为空时，后端使用 `INITIAL_ADMIN_USERNAME` 和 `INITIAL_ADMIN_PASSWORD` 创建首个超级管理员。
5. 系统配置模板会幂等同步。启用 `embedding` profile 时，空的 `PYTHON_EMBEDDING_PRELOAD_MODELS` 仅跳过 v2 拼接层和 v3 融合层的预热；文本编码器仍在服务初始化时加载。需要预热融合层时可显式设置为 `v2,v3`。
6. 文本模型首次加载从 `HF_ENDPOINT` 下载并写入 `huggingface_cache` 卷，默认使用 `https://huggingface.co`。模型源需要支持 Hugging Face SDK 使用的文件元数据和重定向协议；更换源时应使用空缓存验证下载。v3 的训练权重 `fusion_v3.pt` 需要单独放入模型卷，未提供权重时只具备未训练网络的运行能力。

普通重启仍会执行幂等迁移检查，但不会重复创建管理员或覆盖业务数据。首次登录后应立刻修改管理员密码，并从生产环境中移除初始密码。

危险提示：`prisma/seed.ts` 和 `prisma/seed_docker.ts` 都会先删除现有业务数据。正常启动、升级和重启必须保持 `RUN_SEED=false`，也不要手动运行 seed 脚本。`IMPORT_DATA` 也是一次性导入开关，常规运行保持 `false`。

## 更新与停止

更新代码后：

```bash
cd backend
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production logs -f backend nginx
```

停止服务但保留数据库、Redis、上传和模型卷：

```bash
docker compose --env-file .env.production down
```

不要在正常维护中执行 `docker compose down -v`；`-v` 会删除项目数据卷。
